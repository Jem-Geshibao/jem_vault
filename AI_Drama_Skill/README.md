# AI Drama Skill

一组面向 AI 影视与短剧创作的中文工作流指令，覆盖创意开发、剧本分析与改编、角色/场景/道具资产设计、分镜规划、视频拉片和 VR 场景图。每份 Markdown 文档定义一个独立的 skill，可按项目需要单独调用，也可组合成从剧本开发到视觉制作的工作流。

> 本仓库提供的是提示词与工作规范，不是独立运行的软件或模型。实际生成文本、图像、视频或全景图，需要在支持相应能力的 AI 客户端或创作工具中执行。

## 项目特点

- **覆盖影视前期到视觉预演**：从一句创意开始，逐步发展为剧本、制作资产和镜头方案。
- **强调资产连续性**：通过角色、场景和道具的稳定特征与编号，减少跨镜头、跨分段和跨集漂移。
- **提供可执行的输出规范**：包含输入要求、工作步骤、交付格式、质量检查与安全边界。
- **兼顾文字与图像工作流**：既有剧本创作、审计和提示词，也有角色/场景设定板、分镜图及 VR 全景规划。
- **支持独立使用与组合使用**：选择最匹配当前任务的 skill，不必一次调用整套流程。

## 推荐工作流

### 从创意到可制作分镜

1. 使用[影视编剧创作](影视编剧创作.md)确定创意、人物、结构和剧本。
2. 使用[影视剧本分析](影视剧本分析.md)审计因果、节奏、人物选择与对白；需要改编时，使用[影视剧本原创改编](影视剧本原创改编.md)。
3. 使用[剧本资产 DNA 美术指导](剧本资产_DNA_美术指导.md)建立跨场景可复用的视觉基准。
4. 按需求制作角色资产和场景资产，固定角色外观、空间结构、道具状态与编号。
5. 使用[剧本分镜脚本](剧本分镜脚本.md)生成分段视频提示词，或使用[90 秒剧本转视频](90s_script_to_video.md)规划完整单集时间轴。
6. 使用[故事面板](故事面板.md)或[视觉分镜九宫格生成](视觉分镜九宫格生成.md)进行视觉预演；已有参考视频时，用[视频拉片拆解](视频拉片拆解.md)反向分析镜头。

### 角色资产选择

- 需要一张综合设定板：选择[角色设定图](角色设定图.md)。
- 需要严格正交建模参考：选择[角色三视图](角色三视图.md)。
- 只需服装、道具、动作或表情资料：分别选择[角色服装设定](角色服装设定.md)、[角色道具设定](角色道具设定.md)、[角色动作设定](角色动作设定.md)或[角色表情设定](角色表情设定.md)。

### 场景资产选择

- 需要多机位场景展示及空间透视布局：选择[短剧场景布局设计](短剧场景布局设计.md)。
- 需要同一房间的四向正交资产图：选择[场景四视图](场景四视图.md)。
- 需要走位与机位规划：选择[场景俯视布局](场景俯视布局.md)。
- 需要沉浸式完整球形环境：选择[VR 场景图](VR场景图.md)。

## 使用方法

1. 打开与任务对应的 Markdown 文件，阅读其 YAML 元数据、输入门槛和输出规范。
2. 在支持自定义 skill / 指令的 AI 客户端中，按该客户端的规则导入或引用对应文件；不同客户端的目录结构和加载方式可能不同。
3. 提交任务材料，并说明目标、范围、输出语言、时长或画幅等关键约束。
4. 涉及角色或场景资产时，优先提供清晰的参考图；参考资料存在冲突时，明确指定主参考版本。
5. 生成后根据文档中的质检清单进行复核，并将稳定的角色、场景和道具设定继续提供给下游任务。

示例请求：

- “按《影视编剧创作》的流程，把这个故事想法发展成 8 集短剧大纲。”
- “使用《90 秒剧本转视频》规则，把下面这场戏拆成一集完整的 90 秒分镜。”
- “根据这张角色参考图，按《角色三视图》规范生成建模正交视图。”
- “依据这张室内参考图，使用《场景俯视布局》规划演员动线和三个摄影机位。”
- “按《视频拉片拆解》分析这段视频；无法确认的时间点请标注估算。”

## 输入准备建议

- **剧本任务**：提供希望处理的剧本范围，并标明媒介、目标时长、集数、受众及必须保留的剧情事实。
- **角色任务**：提供清晰、尽量完整的角色图，并说明需要的资产类型；不要用互相冲突的参考图要求严格一致。
- **场景任务**：提供可辨认空间关系的参考图；要求精确闭环时，补充侧面、反打或俯视资料。
- **视频分析**：提供可读取的视频或片段；只提供文字描述时，应区分推演分析与对真实视频的观察。
- **跨环节制作**：沿用相同的角色名、资产编号、视觉描述和状态记录，避免下游任务重新设计已锁定资产。

## 使用边界

- 这些文件提供创作流程和生成规范，不保证任一外部模型一定能准确遵循版式、文字或视觉连续性要求。
- 图像、视频、文件解析和全景生成能力取决于所使用的平台；平台不支持时，应输出可执行的提示词或说明限制，不应声称已完成生成。
- 保持原创性与安全边界：避免复刻受版权保护角色或场景、现实公众人物和品牌标识；涉及敏感内容时遵循对应 skill 的安全规则。
- 剧本分析应区分文本证据与推断；对参考图不可见的结构应标为待确认或保守推定。

## 贡献与维护

- 一个 Markdown 文件对应一个边界清晰、可独立调用的 skill。
- 保留 YAML front matter，并确保 `name` 唯一、`description` 能说明触发场景。
- 新增或修改规则时，同步检查输入门槛、执行流程、输出格式、连续性规则、质检清单与安全边界。
- 更新 skill 后同步维护本 README 的分类目录与工作流说明。
- 示例应使用原创、简短内容，不包含真实个人隐私、未经授权的品牌素材或受保护角色仿写要求。
